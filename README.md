# 突发限价预案执行台（油品价格维护扩展）

- 行业：石油
- 技术栈：Vue3、Vite、TypeScript、Pinia
- 启动：`npm install && npm run dev`
- 构建：`npm run build`

在原有“油品价格维护”基础上扩展为突发限价预案的登记—生效—执行—核验—回落闭环。数据保存在浏览器
`localStorage`（key：`dfwlfront-9-limit-console-v1`），刷新后预案、执行、价签与版本完全一致。

## 业务规则

1. **预案登记（整批）**：每行登记区域、油品、限价上限、生效窗口（起止）、适用站点等级，支持多行一批。
2. **整批判定**：
   - 生效窗口必须合法（开始早于结束）；
   - 同区同油品的生效窗口不得交叠（批次内互查，且与既有“待生效/生效中”预案比对，草稿不占窗口）；
   - 等级不符：该区域销售该油品的站点中没有任何所选等级站点；
   - 超限价：限价上限高于油品参考限价。
   - 任一行冲突 → **整批只留草稿**，逐行用颜色标签标明冲突，不生成任何预案；修改草稿后可重新提交。
3. **生效冻结**：进入生效窗口的待生效预案可“立即生效”，或在页面加载时自动补偿生效。生效瞬间按
   `冻结价 = min(生效前挂牌价, 限价上限)` 为范围内每个站点冻结挂牌价与价签快照，生成递增版本号的冻结版本
   （即限价调价单，初始“待生效”）。
4. **站点执行**：站点在执行台上报执行状态（未上报/执行中/已执行/异常）并回传价签价，系统与冻结价逐站核验
   （一致 / 不一致 / 未回传）。
5. **关闭闸门**：价签未全部回传，或存在与冻结价不一致的站点时，**窗口不得关闭、调价单不生效**（按钮禁用并
   给出原因）；全部一致后方可关闭，调价单生效，挂牌价正式落为冻结价。
6. **解除回落**：仅已关闭窗口可解除；解除时各站点按冻结版本中的生效前价格回落，调价单标记“已回落”。
   窗口时刻到期不会自动关闭——仍受价签闸门约束，防止限价期间漏传/错价。

## 分层结构（数据 / 判定 / 存储 / 页面分离）

| 层 | 文件 | 职责 |
| --- | --- | --- |
| 类型 | `src/types.ts` | 预案、批次、冻结版本、价签等领域模型与常量枚举 |
| 数据 | `src/data/catalog.ts` | 站点台账、参考限价、默认挂牌价、适用范围查询 |
| 判定 | `src/domain/rules.ts` | 纯函数：窗口交叠、批次校验、价签核验、关闭闸门、冻结价，无 Vue/存储依赖 |
| 存储 | `src/data/repository.ts` | `localStorage` 序列化/反序列化/损坏兜底/演示种子数据 |
| 状态 | `src/store/console.ts` | Pinia store：编排判定与存储，全部业务操作以 action 暴露 |
| 页面 | `src/components/*.vue`、`src/App.vue` | 登记/执行/挂牌价三个页签，只调用 store action |

页面展开态、输入草稿等瞬态 UI 状态不持久化；业务状态统一以单一根对象持久化，因此刷新后
预案、执行状态、价签快照与版本记录保持一致。
